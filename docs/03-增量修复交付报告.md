## 4. 自选股持久化根因与修复

- **根因**：mock 模式（默认）自选/持仓/规则是模块级内存数组 → 刷新重置。真接口模式 SQLite 已持久化、无 bug。
- **修复**：mock 写操作同步 localStorage（`Kuantix.mock.v1.*` 键），读优先取 localStorage，首次用种子落盘。
- **验收**：mock 模式添加自选 → 刷新页面 → 自选仍在；真接口模式行为不变（已持久化）。

## 6. 回测页功能

- 标的池：D8 搜索添加（最多 20 只），chips 展示 + 移除。
- 策略：19 个上游策略下拉 + 参数表单（按 schema 动态渲染，默认值回填）。
- 参数：时间范围 / 初始资金 / 佣金 / 最低佣金 / 印花税 / 滑点 / 成交价模式。
- 运行：B2 提交 Job → B3 1s 轮询（JobProgress 进度条）→ done 拉 B4。
- 结果：组合指标卡（总收益/年化/最大回撤/夏普/胜率/成交/盈亏比/波动）、组合净值+回撤曲线（ECharts）、逐标的归一化净值多序列、逐标的绩效表 + 成交明细（点击展开）、跳过标的 fail-loud 提示、导出 JSON。
- 引擎：全部经 `BacktestBridge` 调上游 `BacktestEngine` / `PerformanceAnalyzer`（薄包装，R2）；数据读本地 vipdoc（不走网络）；组合视图 = 归一化净值等权平均（聚合，绩效仍由上游计算）。

## 8. 遗留问题与说明

1. **回测数据源**：真接口模式回测依赖本地 vipdoc 已有日线（`~/.Kuantix/vipdoc`）；无数据标的会被跳过并显式计数（skipped），全部失败则 Job failed 422。用户需先 `data sync` 后再跑回测。
2. **组合语义**：P0 组合视图为「逐标的独立回测 + 归一化净值等权平均」，不引入上游 PortfolioBacktestEngine 的资金分仓（与"选股回测"诉求更贴合）。若需资金分仓组合回测，属 P1。
3. **因子数量口径**：上游实测 19 个注册因子；若用户期望"比上游更多"，那是自定义因子扩展需求（P1），不在本次修复范围。
4. **回测结果保留策略**：完整结果存 `~/.Kuantix/db/backtest_results.db`，无自动清理（本地工具，结果量小）；如需历史清理/对比可 P1 加管理端点。
5. **搜索清单刷新**：证券清单缓存 `security_catalog.json` 首次枚举后落盘；若市场有新证券需重新生成缓存（P1 可加刷新端点或缓存 TTL）。
